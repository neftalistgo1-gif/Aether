Organización del proyecto y documentación

Contexto

Aether será un proyecto de largo plazo que combinará backend, frontend, documentación técnica, análisis del negocio y recursos visuales. Conforme crezca, la cantidad de archivos aumentará significativamente.

Decisión
Se organizará el proyecto por responsabilidades:
backend/ para el código del servidor.
frontend/ para la interfaz (cuando exista).
docs/ para toda la documentación.
assets/ para recursos gráficos.
scripts/ para automatizaciones.
La documentación también se organizará por categorías (architecture, business, standards, journal, etc.) en lugar de mantener todos los archivos en un mismo nivel.

Consecuencias

Positivas:

Navegación más sencilla.
Escalabilidad.
Documentación ordenada.
Incorporación más fácil de nuevos colaboradores.

Negativas:

Requiere disciplina para mantener la estructura.
